# PĀṬALA EVAL CONTRACT — the common Inspect benchmark contract

*2026-08-12. With two semantically different SUTs (essay epistemic-laundering and L200 typed-reference
checking) fitting the same Inspect runtime, this freezes the common contract every Pāṭala evaluation MUST
satisfy. It exists so future benchmarks cannot quietly drift into self-grading theatre.*

Every Pāṭala eval MUST declare:

| # | Field | What it means |
|---|---|---|
| 1 | **BENCHMARK NAME + VERSION** | e.g. `PĀṬALA-ARG-LAUNDRY-SYN v0.1` |
| 2 | **CLAIM CLASS** | `SYN \| NAT \| GEN` (synthetic contract / natural adjudication / whole-pipeline) |
| 3 | **SYSTEM UNDER TEST** | exactly defined deterministic checker/function (never the whole runtime) |
| 4 | **INDEPENDENT GOLD** | verdicts NEVER generated by the SUT; from mutation semantics or independent adjudication |
| 5 | **FROZEN SOLVER INPUT** | solver consumes the frozen candidate object, never a mutation recipe or hidden gold |
| 6 | **COMPLETE DATASET HASH** | SHA over `{id, input, expected}` for every sample = hash of the actual corpus |
| 7 | **SUT HASH** | fingerprint of the SUT *implementation only* (e.g. `inspect.getsource(sut)`), isolated from fixture/gold data |
| 8 | **RUNTIME PIN** | exact Inspect version (`inspect-ai==0.3.258`) recorded in the EvalLog |
| 9 | **SPLITS** | construction / dev / held-out where applicable (essential for NAT) |
| 10 | **METRICS** | claim-specific, NA-safe (specificity/sensitivity; NAT: verdict + violation-level + per-family + first-unsupported-layer) |
| 11 | **PROVENANCE** | origin of every sample (esp. natural samples: exact object + how it was produced + independent adjudication) |
| 12 | **BOUNDARY** | explicitly states what passing does NOT establish (SYN ≠ NAT/GEN) |

## The anti-circularity rule (item 4, non-negotiable)

> Gold is "this output is epistemically defective for reason X," not "the detector ought to emit string Y."

The scholarly contract is stable even if the checker implementation changes. A benchmark that derives its
gold from the SUT (or lets a missed mutation become a silent PASS) violates this contract and is not a
Pāṭala benchmark.

## NAT additions (beyond the 12)

NAT datasets need richer scoring than binary SYN:

- object-level verdict accuracy
- violation-level precision / recall
- false-positive rate on naturally clean objects
- false-negative rate on naturally defective objects
- **per-family recall** (authorship laundering, strength inflation, warrant bypass, boundary erasure,
  IA→MT laundering, unsupported expansion, …)
- **"first unsupported layer"** per failure: `SOURCE → SPAN → ATTRIBUTION → SCOPE → WARRANT → CONCLUSION →
  PROJECTION` — where the first epistemic break occurs. This unifies ARG-NAT, L200-NAT and eventually
  TantraFact under one evaluation idea.
- **DERIVATION_STAGE** (for translation-factory tasks like L200): a SECOND, orthogonal axis, because the
  epistemic "first unsupported layer" taxonomy does not naturally describe all factory failures. Values:
  `SOURCE → L0 → L1 → L2 → L200_MT → L200_IA → L200_OPEN → SOURCE_LAYER`. Record `DERIVATION_STAGE`
  alongside `FIRST_UNSUPPORTED_LAYER`; do NOT force an IA→MT classification error into `WARRANT` or
  `PROJECTION` just to unify schemas.
- **adjudicator provenance** — every NAT gold must say exactly who/what produced the adjudication, because
  Agent 1 machine-assigned gold is NOT expert gold:

```json
{
  "adjudicator": {
    "type": "MACHINE | HUMAN | EXPERT | DUAL",
    "agent": "agent1",
    "model": "...",
    "prompt_hash": "..."
  },
  "review_status": "NOT_HUMAN_REVIEWED | HUMAN_REVIEWED | EXPERT_REVIEWED"
}
```

Scholar-reviewed cases upgrade `review_status` separately.

## NAT claim split (do not conflate)

- **L200-CHECKER-NAT** — input `proposal + independently adjudicated reference`, SUT `check_dim`; claims
  "the deterministic checker correctly APPLIES the adjudicated reference." The reference is a legitimate
  solver INPUT (the checker requires one by definition), not hidden gold.
- **L200-DETECTOR-NAT** — input `L0/L1/L2 + proposal` (no reference), SUT a semantic detector; claims "the
  system INDEPENDENTLY identifies MT/IA/open-item defects." Requires a real detector, not `check_dim`.

## Reference implementations

- `source-evidence/evals/inspect_arglaundry.py` — PĀṬALA-ARG-LAUNDRY-SYN (essay epistemic-laundering detector).
- `source-evidence/evals/inspect_l200.py` — PĀṬALA-L200-SYN (L200 typed-reference checker).

Both satisfy items 1–12; new benchmarks must too.
